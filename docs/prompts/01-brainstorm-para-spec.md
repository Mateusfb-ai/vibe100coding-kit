# Prompt: do brainstorm à spec

Cole no início de uma feature. Substitua o que está entre <>.

```
Quero <o pedido, nas minhas palavras>.

Antes de qualquer código: use superpowers:brainstorming. Faça no máximo UMA
pergunta por vez, e só depois de tentar resolver a ambiguidade sozinho lendo
CLAUDE.md, docs/REGRA.md e learnings/.

Saída: specs/<data>-<slug>.md no formato de templates/specs/TEMPLATE.md, com
"como é pronto" em critérios checáveis (comando ou fluxo que prova cada um),
escopo negativo, decisões e suposições declaradas com origem (dono / medição /
suposição), e o gate novo que vai nascer com a mutação.

Não implemente ainda. Não escolha número que eu não aprovei: se faltar um,
diga "não medi, custa X medir".
```
